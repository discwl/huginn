# Native repository metadata contracts

Verified on Windows with Gortex **v0.64.3+56a1c29**, September 10, 2026.

`repos[]` in the host's global config supports `path`, `name`, `workspace`, `project`, `ref`, and `exclude`. `name` is a repository-prefix override, not a plugin display alias. Workspace/project overrides take precedence over repository-local declarations; empty fields inherit local/native defaults. The editor exposes those three identity overrides and the ordered `exclude` list for writing. It displays `ref` without returning unrelated host settings or credentials. `ref` is a label consumed by compatible native query filters (an exact comparison with `RepoEntry.Ref`); it does not check out, fetch or pin a Git revision.

The editor changes the documented YAML configuration directly because there is no public setter for an existing entry's `name`. It uses the YAML document API to retain comments and unrelated keys, validates unique paths/names and field syntax, detects stale global/local config, creates a private backup, then atomically replaces the file. This is an explicit configuration adapter, not a fallback from a failed MCP call. A plugin job coordinates its own writes; unrelated native clients do not share that lock. Backups permit recovery if an external writer races the final comparison/replacement.

After confirmation: save if needed → `gortex daemon reload` → conditionally `workspace_admin` operation `index` with the absolute repository path → reconnect plugin-owned MCP clients → compare configuration against fresh `workspace.info`. Reload is host-wide and can apply other pending configuration edits; the preview states this. Full indexing is restricted to ordinary Git roots with a `.git` directory, matching configured/active graph names and no monorepo project mappings. Directory browsing and ordinary read panels do not trigger it.

Reload alone refreshes configuration and exclusions but does not update the existing indexer's workspace/project stamps. A full index refresh applies those stamps. The operation uses its documented absolute `arguments.path` and explicit subprocess cwd; no speculative checkout selector or unrestricted tool relay is exposed.

Existing graph prefixes remain stable when `name` changes. Gortex 0.64.3 has no supported live graph-rename operation. The plugin therefore saves a confirmed name change but reports a pending daemon update, without untracking, retracking or restarting anything. A mismatch never becomes a successful “applied” result. The library displays configured names separately and uses the actual native member name/workspace for all graph queries. This keeps an existing graph navigable while a new configured identity is pending.

The **Resolve mismatch** action creates a read-only repair preview from fresh native state. With a name mismatch, the proposal replaces the configured name with the active graph name and keeps the user's effective workspace/project values. Existing local inheritance is retained unless adopting the graph name would change its defaults; in that case only the necessary explicit value is saved. The preview shows saved configuration, current daemon metadata and the proposed result side by side. The user can keep the requested name by dismissing it. Nothing is applied until confirmation.

Repair requires a supported selected-repository index refresh and reapplies the unchanged saved exclusion list: correcting the prefix can make previously unbound repo-entry rules take effect. The normal backup, revision/identity preconditions, duplicate-job protection and authoritative verification remain in force. An unavailable daemon, unsupported checkout or already-matching state cannot produce a misleading repair proposal. A failed refresh stays pending; an explicit retry reconciles the saved state and avoids another config replacement when none is needed. This is not a native graph-rename operation, and never forgets or re-tracks a repository.

Save jobs survive client disconnects while the plugin backend remains running. Preview tokens expire after five minutes; duplicate confirmations share one job. A plugin reload discards its in-memory jobs/tokens; the client reconciles config and daemon state before creating another preview. A timeout is not treated as an undo. Successful native responses are validated, and configuration-only, pending, unavailable and failed outcomes remain distinct.

Exclusion editing replaces only the selected `repos[].exclude` list, preserving its order, duplicates, escapes and negations. Empty input removes this entry's list. Host/global and local exclude/include/legacy rules are shown with their source; built-ins and Git ignore files are explicitly not enumerated. These are saved configuration layers, not a complete live exclusion report. Native `config exclude list` has no JSON mode in this version and is not scraped.

An explicit exclusion update always requests a selected-repository index refresh, including a retry with unchanged saved patterns. Reload updates live ignore configuration; rebuilding removes previously indexed files and restores newly included ones. A native index acknowledgement and an unchanged config revision are required to mark exclusions refreshed. Identity equality alone cannot turn a failed or unacknowledged refresh into success. A configured/active name mismatch also leaves exclusions pending: Gortex binds repo-entry rules by native prefix. No source files are deleted. Shared process cleanup, version and checkout gates remain the same as metadata edits.

Validation: built-in Node tests cover backups, comments, integer/line-ending preservation, defaults, duplicate names, stale previews, racing edits, duplicate confirmations, lost acknowledgements, host-path authorization, plugin reload and graph/config identity separation. The explicit `node --experimental-strip-types server/metadata-native-fixture.ts` exercise starts an isolated daemon with two temporary repositories, applies a workspace/project move through the actual adapter and verifies that the other repository is unchanged. It also adds an exclusion, verifies the excluded symbol disappears while a negated pattern keeps another symbol, clears the list and verifies restoration. The second repository stays searchable and source files remain on disk. Unit cases cover failed refreshes, stale inherited rules, ordered patterns, removal and explicit retry. It stops only that fixture daemon. Windows foreground startup was not reachable in this fixture; the supported detached startup path works.
